# noise-field

Полевой шумомер для одного человека: замер уровня с координатами и счётом
автотранспорта, выгрузка CSV для внешней валидации акустической модели проекта
noise-map.

Реализовано по `noise-field-spec.md`, макеты — `screens.html`. Спецификация —
контракт; скрипт валидации пишется под неё, а не наоборот.

## Сборка

```bash
./gradlew :app:assembleDebug
```

Нужен **JDK 17 или 21** — AGP 8.7 на JDK 25 не запускается. В репозитории нет
`gradle/wrapper/gradle-wrapper.jar` (бинарник); он появится после первого
открытия проекта в Android Studio либо после `gradle wrapper` с локально
установленным Gradle 8.9.

Юнит-тесты (без устройства):

```bash
./gradlew :app:testDebugUnitTest
```

Тест схемы БД — на устройстве или эмуляторе:

```bash
./gradlew :app:connectedDebugAndroidTest
```

## Что где

| Пакет | Что |
|---|---|
| `data` | Room: `Calibration`, `Measurement`, `VehicleEvent`, репозиторий, инкремент ID точки |
| `audio` | A-взвешивание, банк октавных полос, арифметика уровней, захват с AudioRecord |
| `session` | Foreground service захвата, GPS, шина живого состояния |
| `export` | Сборка четырёх CSV и отдача через `ACTION_SEND_MULTIPLE` |
| `ui` | Четыре экрана: выезд (стартовый), замер, карточка точки, калибровка |

## Решения, принятые явно

**Полюса A-взвешивания стандартные и под тест не подгоняются.** Прямое билинейное
преобразование прототипа IEC 61672 на 44100 Гц даёт на 8 кГц −0.71 дБ — это
частотное искажение метода, а не ошибка реализации. Допуск в тесте расширяется к
краям, как его и задаёт сам стандарт: ±0.5 дБ в полосе 63 Гц – 4 кГц, ±1.5 дБ на
8 кГц, ±2 дБ на 31.5 Гц. Фактические отклонения — от 0.00 до 0.13 дБ везде, кроме
8 кГц. Сдвигать полюса, чтобы пройти узкий допуск, нельзя: получается фильтр,
проходящий собственный тест и переставший быть A-взвешиванием, а вся конструкция
держится на сравнимости с прибором класса 2.

**Октавы считаются в поле и хранятся всегда.** Аудио не сохраняется, значит
спектр задним числом не восстановить ничем, кроме новой поездки. Полосы 63…8000 Гц,
по одному бикваду на полосу (Q = √2), по невзвешенному сигналу, с офсетом. Один
биквад даёт −3 дБ на границах полосы, но только −7.4 дБ на центре соседней: полосы
подслушивают друг друга, и для оценки наклона спектра этого мало. Если понадобится
точнее — каждая полоса собирается каскадом из трёх таких же биквадов.

**`id` в CSV суррогатный, `point_id` — отдельная колонка.** Повтор ID точки не
ошибка, а обязательная часть датасета: контрольный замер тех же точек через
несколько дней даёт порог достижимой точности. Связи `series.csv`, `vehicles.csv`
и `octaves.csv` идут по суррогатному ключу, предупреждений о дублях нет.

**Счётчики раздельные.** `light_total` / `heavy_total`: сумма из пары выводится,
разделение из суммы — нет.

**Координаты — медиана, точность — от лучшего фикса, флаг — от худшего.** За
пятнадцать минут на месте фиксов накапливается много, и медиана широты и долготы
по фиксам точнее 10 м устойчивее любого одиночного.

**Уровни хранятся с офсетом, усредняются по энергии, состояние фильтров не
сбрасывается между буферами, посекундный ряд пишется всегда, флаги не удаляют
данные, аудио не сохраняется.** Всё по §8, каждое место помечено комментарием
в коде.

**GPS — голый `LocationManager`, спутниковый провайдер.** Без Play Services:
работа полевая и офлайновая. Сетевая геолокация не рассматривается — её точность
на два порядка хуже порога в 10 м.

**Нелинейность калибровки — вычисляемое состояние, а не поле.** `spreadDb > 1.5`
показывается чипом и на калибровке, и на экране замера; отдельного флага в схеме
нет, чтобы не заводить второй источник правды.

**Калибровка требует размаха уровней.** Три пары на одном уровне проверяют точку,
а не наклон: при размахе меньше 15 дБ показывается предупреждение, ниже 20 дБ —
мягкая заметка. Сохранение не блокируется ни там, ни там.

**Шрифты системные.** IBM Plex из макета требует бинарников в репозитории или
загрузки через Play Services; в поле важнее, чтобы приложение открывалось офлайн.
Все числовые поля — моноширинные и с табличными цифрами (`tnum`), иначе крупный
`LAeq` дёргается по ширине при каждом обновлении.
